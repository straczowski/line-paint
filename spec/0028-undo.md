# 0028 Undo

## What

Command+Z undoes the last committed change to the drawing. The shortcut is handled while either tool is active, including when nothing is left to undo, so the browser does not take it. Key repeat walks back one further step per repeat. Command+Z during a pointer gesture does nothing. The gesture still becomes one step when the pointer goes up.

The past holds the newest 100 steps. The step older than that is dropped. Each step is the drawing plus the editor state that belongs with it: the selection, the entered group, point editing, and the duplicate offset. Command+Z restores that whole step. The tool, the draft, and the viewport stay as they are.

A step is recorded only when the committed drawing differs from the current one: polyline order, points, `closed`, stroke, width, or group ids. A zero move, a scale that stays at the same size, a group or ungroup that changes nothing, and a finish with fewer than two points take no slot.

These commits are one step each:

- Finish a polyline, with Enter or the Finish button
- Move the selection, including a Shift-locked move
- Scale the selection
- Duplicate, whether by Alt-drag or by Command+D
- Move a point
- Insert a point
- Delete a point
- Delete the selection, whether by Backspace or the delete button
- Toggle open or closed
- Import an SVG, whether from the menu or a drop
- Group
- Ungroup

A new scene change uses the same commit. It does not keep its own undo path. The history value and the rule that pushes and restores a step live in one pure module, `src/ui/history.ts`. React holds the past. The shortcut stays in `src/ui/commands.ts`.

The harness says this in the places an agent reads before adding a feature:

- `docs/CONCEPT.md` describes undo, the 100-step past, and the commits listed above
- `docs/ARCHITECTURE.md` names `src/ui/history.ts` and says a scene change is a call to that commit
- `.agents/skills/write-spec/SKILL.md` says a spec that changes the scene names its undo step and routes that change through the commit

## Out of scope

- Redo, Command+Shift+Z, and a future stack
- An undo button
- Control+Z
- Selection, Shift-click, marquee, entering a group, and leaving a group
- Pan, zoom, and fit
- Switching tools
- Export, including GCode travel order
- A refused import
- Points of an unfinished draft. Finish is the step. Command+Z leaves the draft on screen
- Persistence of the past across a reload

## Pitfalls

CONCEPT.md has no undo. This spec adds it. The Selection, Polyline tool, and Import sections stay the behavior of those commits. Undo is its own section.

DESIGN.md says a shortcut may exist and the control still has to make sense without it. 0019 and 0027 already use a command shortcut with no button. Undo follows that. A button would change the plotted line, and this spec leaves it out.

0017 previews a move on the overlay and writes the scene when the pointer goes up. That single write is why a drag is one step. Recording pointer moves would fill the 100 slots during one gesture.

A click that becomes a move of zero still builds a new polyline list in `translatePolylines`. Reference equality is not enough. The commit compares the drawing fields above and skips a match, so an empty gesture does not spend a slot.

Undo of a duplicate, a delete, an import, or a point edit restores the selection and the related editor state from before that commit. Restoring only the polylines would leave the selection on ids that the undo removed, or would leave point editing on an index the undo put back. Those fields are editor state, as the duplicate offset is in 0019 and the entered group is in 0027. They ride along in the step. They are not fields on the polyline.

Command+Z restores the selection from that step, so a click made after the commit is left behind. Selection itself is not a step.

The draft is not a step. Undoing while a draft is on screen changes the committed sheet and leaves those draft points. Removing the last draft point is a different gesture.

ARCHITECTURE.md keeps scene math free of React. History is a value: a list of at most 100 snapshots. `src/ui/history.ts` only computes that value, which is the pure-ui case the module list already allows. No state library. The scene files keep move, scale, duplicate, points, groups, import, and open or closed. They do not grow an inverse for each one.

CODING.md's KISS is this shape. One snapshot stack covers a later action because that action already returns a new scene. A hand-written inverse per action is the path that forgets the next feature. The 100 cap is the product cut: a step is the polyline list, and 100 of those is a sitting's worth of undos. YAGNI leaves redo and a button to a later spec. Adding redo means keeping the step Command+Z currently discards.

## Done when

- Command+Z restores the previous drawing, selection, entered group, point edit, and duplicate offset for each commit listed above. A second press restores the step before that.
- The 101st commit drops the oldest step. After the past is empty, Command+Z changes nothing and still does not go to the browser.
- A commit whose drawing fields match the current scene adds no step. A press with no drag is this case.
- Command+Z during a pointer gesture changes nothing. Pointer up still records one step when the drawing changed.
- An unfinished draft stays put across Command+Z.
- Pan, zoom, fit, selection clicks, tool changes, and export add no step.
- CONCEPT.md, ARCHITECTURE.md, and the write-spec skill say that a scene change commits through `src/ui/history.ts` and that the spec for that change names the undo step.
- Tests cover a restore, the 100-step cut, a no-op commit, and Command+Z. `npm test` and `npm run build` succeed.
